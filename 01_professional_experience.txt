Machine Learning and Statistical Modeling — Wind Turbine Project:
One of the most impactful projects at Sonline involved an energy sector client operating wind turbines. The client had vibration sensor data from turbine components but no systematic way to identify early-stage mechanical degradation before it led to failures.

What Rithujaa did:
- Ingested and cleaned large time-series vibration sensor data from wind turbine components using Python and Pandas
- Applied Isolation Forest, an unsupervised machine learning algorithm, to detect anomalies in the sensor readings
- Isolation Forest works by randomly partitioning data and flagging points that are isolated quickly as anomalies — it is well suited for unlabeled time-series sensor data where no historical failure labels exist
- Applied survival analysis to model equipment degradation over time and predict when components were likely to fail
- Achieved 0.91 precision — meaning 91% of the anomalies flagged by the model were genuine early-stage mechanical problems
- Built a Power BI dashboard showing risk scores for each turbine component, color-coded by severity
- Communicated findings to the client's operations team in plain language, explaining which turbines were at risk and when action was needed

The result: the client's maintenance teams shifted from reactive maintenance (fixing things after they break) to proactive maintenance (preventing failures before they happen), significantly reducing downtime and operational costs.

Why Isolation Forest was chosen:
Isolation Forest was the right tool because the sensor data was unlabeled — there was no historical record of which readings corresponded to actual failures. Isolation Forest can detect anomalies without needing labeled training data, making it ideal for this use case.

ROLE 2: DATA SCIENCE INTERN
Company: Trilemma Foundation
Duration: September 2025 to December 2025 (4 months)
Type: Internship, Remote

What Trilemma Foundation Does:
Trilemma Foundation is a financial research organization focused on developing data-driven investment strategies using alternative data sources, machine learning, and AI. They research how non-traditional data signals — like social sentiment, crypto on-chain metrics, and macroeconomic indicators — can be combined to create better financial strategies.

The Problem Being Solved:
Traditional quantitative finance strategies rely heavily on price data, volume, and simple technical indicators. The research question at Trilemma was: can we use alternative data sources — particularly natural language sentiment from financial news and on-chain crypto data — to build a more predictive strategy?

What Rithujaa Built:

Feature Engineering (369 features across 3 categories):
1. On-chain crypto metrics — blockchain-level data including transaction volume, active addresses, miner revenue, and network hash rate
2. Macroeconomic indicators — interest rates, inflation data, unemployment figures, and other macro signals
3. NLP sentiment signals — sentiment extracted from financial news and text using multiple models

NLP and LLM Pipeline:
- FinBERT: A BERT-based model specifically pre-trained on financial text. Used to extract sentiment from financial news articles. Far more accurate than general sentiment tools because it understands financial language nuances.
- RoBERTa: A more powerful general NLP model used for deeper text understanding and classification.
- VADER: A rule-based sentiment analysis tool used for quick baseline sentiment scoring.
- GPT-4o (OpenAI API): Used for more complex tasks — summarizing financial reports, extracting structured insights from unstructured text, and automating analytical tasks that required genuine language understanding.

The 6-Agent Ensemble:
Rithujaa built a 6-agent ensemble ML strategy where each agent specialized in a different combination of signal types:
- Agent 1: On-chain signals only
- Agent 2: Macro signals only
- Agent 3: NLP sentiment signals only
- Agent 4: On-chain + Macro combined
- Agent 5: On-chain + NLP combined
- Agent 6: All signals combined

The ensemble combined the outputs of all 6 agents using weighted averaging, making the system robust — if one signal type was noisy in a given period, other agents compensated.

Backtesting and Validation:
- Validated the strategy across 3,075 rolling 12-month backtesting windows
- Applied statistical significance testing to ensure results were not due to chance
- Achieved a 90.37% win rate over the baseline strategy — meaning the ensemble outperformed the baseline 9 out of 10 times across all testing windows

Data Pipeline:
- Built scalable Python pipelines to collect, clean, and transform financial data from multiple sources
- Automated data collection, transformation, and feature engineering workflows end to end
- Ensured data quality at each step with validation checks

Streamlit Dashboard:
- Built an interactive Streamlit dashboard to monitor strategy performance KPIs in real time
- The dashboard displayed win rates, signal breakdowns, and feature importance across testing windows
- Made it easy for non-technical researchers to understand what was driving the strategy's performance
